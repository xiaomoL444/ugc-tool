# 预设系统默认配置

实体新增 `guid`（GUID 数字文本）与 `entityQuery`（实体查询字符串），新建及旧自定义条目缺失时默认空字符串；内置玩家自身的 `guid` 为 `1086324738`，实体查询为空。旧系统快照按系统 ID 补默认值，已有合法值（包括显式空值）不覆盖；GUID 不经过 Number 转换。两个字段均可在实体预设中编辑并自动保存，系统项只读。

“触发实体朝向（仅物件）”的两个 GUID 参数引用 `entities.guid`，两个 String 参数引用 `entities.entityQuery`。下拉按实体名称和实际值显示，过滤空查询和无效 GUID，同时保留手动输入。旧动作按事件名和参数 ID 提供候选，不修改原值或显式引用；选择只复制值，后续修改实体预设不回写动作。自定义公共事件也可将这两个实体字段设为兼容类型的值来源。

对话样式额外提供布尔字段 `showTitle`（显示标题）。系统 `NOLOC_Default`、`NOLOC_BottomDialog` 为 true，其余系统样式与新建自定义样式为 false；系统项仍只读，自定义项可切换。旧文件缺失字段时，按类型值匹配系统默认，否则补 false；合法 true/false 保留，其他类型报错且不覆盖文件。工作区候选同时携带此设置，文本编辑按其显示说话人（Title / Talker）和 Subtitle；关闭时运行时导出将二者写为空字符串，工程原文保留。导出使用当前工作区预设，读取失败时需重试，避免误用系统默认。

相机预设同样接入通用模块：系统项“默认镜头 / Default”只读置顶，自定义项保存在工作区 `cameras.json`。显示名称用于选择，相机名称写入 Timeline 的 `cameraName`；相机编辑器仅通过预设选择镜头名称，保留已失效的旧值供显示，不再提供独立手填框。相机预设的保存队列随其他类别一同在离开编辑器前刷新。

开发者统一在 `systemPresetConfig.ts` 维护系统配置：`newItem` 为新建自定义条目的字段默认值，`presets` 为所有工作区始终可用的只读系统列表。人物、技能动画、对话类型、任务样式及边走边说类型均已接入。人物内置“玩家自身”：`name="玩家自身"`、`talker="{1:ps.NICKNAME}"`、`subtitle=""`。技能动画内置交谈-持续（1098907649）、交谈-后摇（1098907651）、抱胸-持续（1098907652）、抱胸-后摇（1098907654）。

对话类型内置 `Default_UI`、`Black_Screen`、`Clear`，任务样式内置 `Mainline`，边走边说类型内置 `Default`。三类均在预设设置中管理显示名称与实际类型值，分别保存到工作区 `dialogueStyles.json`、`questStyles.json`、`walkTalkStyles.json`。对话文本和 Timeline 共用一份工作区选项，任务保留手填入口。缺失、删除或更名的预设不会重写已有内容的类型值；空值草稿不进入下拉，重复类型值只显示第一项。新建内容的原有默认值保持兼容，预设仅管理候选列表。

例如人物项的格式是 `{ id: "system-person-a", name: "网页代号", talker: "人物名", subtitle: "副标题" }`；技能动画项是 `{ id: "system-animation-a", name: "动画名", configId: "真实配置ID" }`。人物的 `name` 只用于网页显示，添加对话仍复制 Talker 和 Subtitle；代号为空时显示 Talker，旧文件缺少代号时以原 Talker 补齐。技能 ID 必须替换为有效的非负 Int32 整数文本。系统条目的 id 应稳定且在同类列表内唯一。

- 上方系统区只显示文本，不能修改或删除；下方自定义区可新增、编辑、删除。没有恢复默认入口。
- `systemPresets` 是只读系统列表，`presets` 是可编辑的工作区自定义列表，`availablePresets` 合并两者供消费端选择，系统在前。同类型值的样式选项优先采用系统项。
- 工作区只保存自定义列表，并标记 `presetStorage: "custom-only"`。加载本身不写文件；空自定义列表不会隐藏系统项，也不会复活已删除的自定义项。
- 旧版混合文件中，与当前系统项完全一致的快照不再列入自定义区；曾改动的系统快照保留为独立自定义条目并换用不冲突的 ID。已有对话或 Timeline 的值不改写。
- 损坏文件保留并报错；读写失败重试、离开前保存和工作区隔离统一由 `useWorkspacePresets.ts` 处理。
- 修改预设不会回写已经创建的对话或 Timeline 动作的值；公共事件的显示条件按下述规则同步。

## 新增类别与字段

1. 在 `systemPresetConfig.ts` 添加该类别的 `newItem` 和 `presets`；新增字段也在这里声明默认值。
2. 定义类型与编解码器，新增字段为旧文件补默认值，但不得覆盖已有合法值。
3. 新建条目从该类别的 `newItem` 复制，并生成独立 id。
4. 用 `useWorkspacePresets` 注册文件名、编解码器和必填的 `defaults` 工厂；不要另写一套自动保存逻辑。
5. 在预设设置增加上方只读系统区和下方自定义编辑区，将 `flush` 接入 `prepareToLeave`；消费端使用同一 hook 的 `availablePresets`。
6. 验证系统只读、合并顺序、旧数据迁移、自定义清空后系统项仍在和保存失败重试。

## 公共事件预设

系统内置“玩家传送”（`NOLOC_PlayerTeleport`），入参按位置 X、位置 Y、位置 Z、旋转 Y 排列，均为 Float，默认值为 0，按此顺序写入 `floatParams[0..3]`。

参数可用 `visibleWhen: [{ parameterId, equals }]` 配置显示条件，多个条件按“且”组合；自定义公共事件的参数编辑区提供条件配置。条件按稳定参数 ID 引用，更名或重排不影响引用，删除来源后保持字段显示以便修正。显示条件跟随当前预设：预设成功保存或对话重新打开后，按已保存的预设 ID、参数 ID 和类型同步现有 Clip 的条件，包括未打开参数面板的片段；新增、修改和删除条件均生效。事件名、参数值、来源和结构仍保留原快照；预设缺失或参数 ID／类型不匹配时保留原条件。隐藏不会清除已填写值；导出前同步整个当前对话的条件，隐藏参数使用字符串空值或数值 0 占位，保留各类型参数列表的顺序。

公共事件的手填参数、默认值、条件匹配值及自定义配置记录使用 `TypedValueInput.vue`，按数据类型限制键入和粘贴：Int32 支持正负整数；Float 支持小数和科学计数；GUID、配置 ID、元件 ID 仅接受非负整数文本；String 自由输入文字。条件匹配值使用来源参数的类型，来源缺失时保留文字编辑能力。数值输入允许负号、小数点和指数等中间草稿，失焦后标记未完成或超范围的值；空值仍可作为可选草稿，导出继续校验必填数值。非法整段输入直接拒绝，不将小数或文字拆成其他数字；GUID 不经过 Number 转换，切换类型和加载旧数据不会自动改写值。

“触发实体朝向（仅物件）”始终显示实体1配置，第一个参数为 0 时重置实体1并隐藏实体2，为 1 时显示两组实体配置；每组按 GUID（0）或 String（1）只显示对应的输入。

系统内置“重置镜头”（`NOLOC_ResetCamera`），参数“是否立即到达”为 Int32，来源为 `booleans.value`，默认否（0）。布尔值仅提供只读的否（0）、是（1）；实体获取方式仅提供只读的 GUID（0）、String（1）。这两个固定类别不显示自定义区，也不能新增或编辑自定义预设；消费端仅使用系统选项。旧工作区自定义文件保留，不加入候选列表，不改写已有 Clip。Timeline 仅提供预设下拉选择，导出至 `intParams`。

系统内置“播放简单黑幕”（`NOLOC_SimpleBlackScreen`）：颜色为 String，默认 `#000000FF`，写入 `stringParams[1]`（索引 0 为事件名），由游戏端解析 `#RRGGBB` 或 `#RRGGBBAA`；过渡时间、持续时间、淡出时间为 Float，默认依次为 `0.5`、`1`、`0.5`。浮点参数按同类型顺序写入新版 ActionClip 的 `floatParams`（FloatList），并校验有效数值及浮点范围。

系统内置“玩家播放技能动画”，事件名 `NOLOC_PlayerSkill`。参数“技能配置 ID”为 `ConfigReference`，引用 `skillAnimations.configId`，默认值为空，使用时选择技能动画。

公共事件按“代号（alias）、事件名（name）、参数（parameters）”配置。代号仅用于网页显示与搜索，不写入事件名或导出参数；未填写代号时显示事件名。旧文件缺少 alias 时以原事件名补齐，显式空代号保留。系统项仍只读置顶。

在「预设公共事件」中配置事件名，以及每个参数的名称、类型和默认值。事件名写入 `NOLOC_TRIGGERPUBLIC` 的 `stringParams[0]`，字符串参数从索引 1 开始；整数、GUID、配置 ID、元件 ID 分别写入 `intParams`、`guidParams`、`configParams`、`prefabParams`，各自从索引 0 开始并保持同类型参数的定义顺序。

Public Event Clip 通过预设下拉选择事件，不提供独立事件名输入框。套用预设时复制事件名和参数定义并按名称显示参数输入框，GUID 保留为文本以避免精度丢失。预设及参数引用的弹出菜单标记为 Clip 编辑器区域，点击选项不会触发外部关闭。修改预设仅自动同步已有 Clip 的显示条件；重新选择同一预设时刷新其余定义，并按参数 ID 和类型保留已填写的值。旧版单字符串预设迁移为一个字符串参数，旧 Clip 的事件名保持原值；预设缺失时只读提示已保存的事件名。

预设由 `useWorkspacePresets` 保存在工作区的 `PublicEventPresets.json`；系统条目与新建默认值统一定义在 `systemPresetConfig.publicEvents`，系统条目只读。

## 多字段自定义配置与公共事件引用

系统配置类别内，上方展示只读系统字段，下方可以新增、编辑、删除自定义字段。系统记录的名称及系统字段值只读，其自定义字段值可以填写；用户新增的记录可以编辑全部字段。系统类别和字段仍在 `systemPresetConfig.customTables.presets` 中定义，目前系统类别列表为空。

用户扩展以独立条目保存在 `CustomPresets.json`，通过可选的 `extends` 指向系统类别 ID，只保存新增字段及用户填写的记录值。消费端的 `availablePresets` 按系统类别 ID 合并，公共事件可引用合并后的全部字段；系统字段和系统记录原值优先，不能被扩展覆盖。系统类别移除后仍保留扩展及原引用 ID，显示为可编辑的自定义类别；已有无 `extends` 的自定义类别保持兼容。

「自定义配置」可创建多个类别。每个类别包含字段定义（稳定 ID、名称、数据类型）和记录（稳定 ID、显示名称、按字段 ID 保存的值）。支持字符串、整数、配置 ID、元件 ID、GUID；数值均以字符串保存，GUID 不转换为 JavaScript Number。字段更名不会丢失记录值，新增字段不会覆盖旧数据。文件为工作区 CustomPresets.json，默认字段集中在 systemPresetConfig.customTables。

公共事件参数的“值来源”可以选择兼容类型的预设字段，包括技能配置 ID、实体人名/副标题、样式值、事件名和自定义字段。reference 保存来源键，自定义键由类别与字段 ID 编码组成。Timeline 提供记录下拉，选择时只复制字段值；已保存的 Clip 保留来源信息和值，导出仍按原来的类型列表写入。配置了值来源的参数仅显示记录下拉，不同时提供手动输入框；未配置来源时才显示输入框。来源被删除或更改类型时保留原值，并提示在预设设置中修正来源，不依赖来源存在才能导出。单个来源读取失败不会禁用其他来源的下拉。

配置页采用分类导航，各分类保持挂载以保留自动保存队列；所有保存队列均纳入离开前刷新。公共事件使用完整宽度的参数卡片，窄窗口切换为两列字段；自定义记录表格可横向滚动，字段数量不需要硬编码 UI。

所有可编辑预设分类均支持工具栏撤销／重做及 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+Y，当前分类保留最近 100 步，切换分类后仍可恢复。类别、字段、记录及公共事件参数的增删改都纳入历史，删除字段可连同其全部记录值一起恢复；系统条目不进入可编辑快照。恢复结果仍自动保存。接入与文档边界见 [编辑历史](../EDITOR_HISTORY.md)。
