# 预设默认配置与工作区编辑

公共事件、实体、技能动画、对话类型、任务样式、边走边说类型和相机均由系统配置提供默认值。界面上方为淡底系统预设卡片，下方为自定义预设。系统代号和显示名称固定，不提供新增、删除系统项的操作；事件名、参数、人物信息、技能配置 ID、样式值等实际内容可以修改。自定义项仍可自由新增、编辑和删除。修改后自动保存到当前工作区，没有恢复默认入口。实体获取方式的 GUID（0）和 String（1）是固定协议选项，继续保持只读；多字段自定义配置的系统字段扩展规则见后文。

实体新增 `guid`（GUID 数字文本）与 `entityQuery`（实体查询字符串），新建及旧自定义条目缺失时默认空字符串；默认玩家自身的 `guid` 为 `1086324738`，实体查询为空。旧默认快照按默认 ID 补字段默认值，已有合法值（包括显式空值）不覆盖；GUID 不经过 Number 转换。两个字段均可在实体预设中编辑并自动保存，包括默认项。

“触发实体朝向（仅物件）”的两个 GUID 参数引用 `entities.guid`，两个 String 参数引用 `entities.entityQuery`。下拉按实体名称和实际值显示，过滤空查询和无效 GUID，同时保留手动输入。旧动作按事件名和参数 ID 提供候选，不修改原值或显式引用；选择只复制值，后续修改实体预设不回写动作。所有公共事件参数都可将这两个实体字段设为兼容类型的值来源。

对话样式额外提供布尔字段 `showTitle`（显示标题）。默认 `NOLOC_Default`、`NOLOC_BottomDialog` 为 true，其余默认样式与新建样式为 false；每个条目都可切换。旧文件缺失字段时，按类型值匹配系统默认，否则补 false；合法 true/false 保留，其他类型报错且不覆盖文件。工作区候选同时携带此设置，文本编辑按其显示说话人（Title / Talker）和 Subtitle；关闭时运行时导出将二者写为空字符串，工程原文保留。导出使用当前工作区预设，读取失败时需重试，避免误用初始默认值。

相机预设同样接入通用模块：系统提供“默认镜头 / NOLOC_Default”，显示名称“默认镜头”固定，实际相机名称可修改；下方可添加自定义条目，保存在工作区 `cameras.json`。显示名称用于选择，相机名称写入 Timeline 的 `cameraName`；相机编辑器仅通过预设选择镜头名称，保留已失效的旧值供显示，不再提供独立手填框。相机预设的保存队列随其他类别一同在离开编辑器前刷新。

开发者统一在 `systemPresetConfig.ts` 维护初始配置：`newItem` 为新增自定义条目的字段默认值，`presets` 为系统默认种子列表；UI 不另写一套默认值。人物系统项“玩家自身”的代号固定，默认 `talker="{1:ps.NICKNAME}"`、`subtitle=""`，实际人物信息及实体参数可编辑。技能动画默认包含交谈-持续（1098907649）、交谈-后摇（1098907651）、抱胸-持续（1098907652）、抱胸-后摇（1098907654）等真实配置 ID；系统动画名称固定，配置 ID 可编辑。

工作区「… → 设置结构体 ID → 读取 GIL」也可按技能名称同步技能动画配置 ID。弹窗先展示识别结果，点击保存后才通过 `useSkillAnimationPresets` 更新现有系统项和自定义项；未匹配项保留原值，同名多个 ID 可选候选或保留现有值，不自动新增技能。保存继续使用 `system-overrides` 格式和工作区隔离；成功接收外部保存快照的缓存预设编辑器重置该分类历史基线，避免之后撤销恢复导入前的旧 ID。已有动作的技能参数仍保留复制时的值，需要重新选择动画。

对话类型默认提供 `NOLOC_Default`、`NOLOC_BlackScreen`、`NOLOC_BottomCG`、`NOLOC_BottomDialog`、`NOLOC_Clear`，任务样式默认提供 `NOLOC_Mainline`，边走边说类型默认提供 `NOLOC_Default`。三类均在预设设置中管理实际类型值，系统显示名称固定，自定义条目可同时管理显示名称；分别保存到工作区 `dialogueStyles.json`、`questStyles.json`、`walkTalkStyles.json`。对话文本和 Timeline 共用一份工作区选项，任务保留手填入口。预设变更不会重写已有内容的类型值；空值草稿不进入下拉，重复类型值优先显示系统项，其次为第一项自定义预设。预设仅管理候选列表；边走边说新增和插入台词默认使用 `NOLOC_Default`，推进延迟默认为 2 秒。

选项卡样式在「预设设置 → 选项卡样式」管理，系统项“默认样式 / Default_UI”由 `systemPresetConfig.ts` 提供，显示名称和类型值固定，参数可以编辑；下方可新增、编辑和删除自定义样式。保存到当前工作区 `selectStyles.json`，复用通用加载、保存、撤销和离开前刷新流程；以 `system-overrides` 分开保存系统参数覆盖和自定义项，旧混合文件中修改过系统名称或类型值的快照仍保留为自定义项。Timeline 的 Select Clip 从工作区候选读取样式，也可作为公共事件字符串参数的预设值来源。空值草稿不进入下拉，重复值优先显示系统项；旧工程中已失效或未知的样式仍显示为“当前值”，不会被覆盖，运行时导入和导出继续原样保存样式字符串。

对话类型和选项卡样式的系统项、自定义项均有独立的全宽「参数设置」折叠区。参数定义为 `{ id, name, type: "Int32", defaultValue, reference? }`，名称用于节点显示，类型固定为整数；默认值以字符串保存并由 `TypedValueInput.vue` 校验。值来源可选手动填写或兼容整数的预设字段（Int32 与配置 ID），按列表顺序定义至多 100 项，可新增、删除、上移和下移。新参数默认值集中在 `systemPresetConfig.styleParameters.newParameter`，旧样式文件缺少参数列表时补空列表。折叠只改变界面显示，保留输入内容，不写入预设或撤销历史；参数增删改、排序和来源选择均进入当前分类历史并自动保存。

文本节点与选项卡节点按当前类型的参数名称提供整数填写控件，节点不再新增、删除或调整入参顺序；手动参数提供整数输入，配置值来源的参数提供记录下拉。选择类型时复制参数定义和默认值，来源记录选择只复制整数文本；无效或不存在的来源保留当前值并提示修正。Clip 的 `parameterPreset` 保存定义快照，实际值仍分别保存在对话的 `nodeGraphEvent` 和选项卡的 `params` 中，运行时按原有整数列表顺序导出。已绑定节点不会因修改预设而被改写；定义变化后可点击「应用预设参数（恢复默认值）」复制新定义并恢复默认值，重新选择类型也使用该类型的默认值。读取尚无快照的旧节点时，先等待工作区样式载入，按位置保留已有入参，超出定义列表的旧值以「旧参数」继续显示；未知类型的旧值保持原样。

例如人物项的格式是 `{ id: "system-person-a", name: "网页代号", talker: "人物名", subtitle: "副标题" }`；技能动画项是 `{ id: "system-animation-a", name: "动画名", configId: "真实配置ID" }`。人物的 `name` 只用于网页显示，添加对话仍复制 Talker 和 Subtitle；代号为空时显示 Talker，旧文件缺少代号时以原 Talker 补齐。技能 ID 必须替换为有效的非负 Int32 整数文本。默认条目的 id 应稳定且在同类列表内唯一。

- 普通类别上方展示系统预设默认值，下方展示自定义预设。系统卡片保留淡色底和固定代号，值可编辑；系统项不可新增或删除，自定义项可自由增删改。
- 这些类别以 `editableDefaults: true` 接入 `useWorkspacePresets`，并用 `fixedFields` 声明系统固定字段。实体和技能动画固定 `name`，公共事件固定 `alias`，样式和相机固定 `label`；选项卡样式额外固定 `value`，仅其参数定义可编辑；其他合法字段保留工作区值。
- `presets` 是系统值与自定义项共同组成的完整编辑历史状态，`systemPresets` 暴露其中可编辑的系统对象，`customPresets` 是可写的自定义列表视图，`defaultPresets` 是只读种子；消费端使用系统在前的 `availablePresets`。新增或删除自定义项通过给 `customPresets` 赋值回写，不能直接向其筛选结果数组追加元素。
- 工作区标记 `presetStorage: "system-overrides"`，`presets` 只保存自定义项，`systemOverrides` 仅保存可编辑值与种子不同的系统条目快照。加载本身不写文件；空自定义列表不影响系统项，清空自定义项后不会复活已删除的自定义条目。
- 旧 `custom-only`、无标记混合文件和 `workspace` 完整列表读取时补回缺少的系统项，系统固定字段采用种子，已有合法的可编辑值保留。`custom:<系统 ID>` 快照保留原自定义 ID，维护已有 Clip 的预设引用；已有对话或 Timeline 的值不改写。后续保存为系统值覆盖与自定义项分开记录的格式。
- 固定实体获取方式及多字段自定义配置继续使用原有存储模式，规则见各自说明。
- 损坏文件保留并报错；读写失败重试、离开前保存和工作区隔离统一由 `useWorkspacePresets.ts` 处理。
- 修改预设不会回写已经创建的对话或 Timeline 动作的值；公共事件的显示条件按下述规则同步。

## 新增类别与字段

1. 在 `systemPresetConfig.ts` 添加该类别的 `newItem` 和 `presets`；新增字段也在这里声明默认值。没有真实默认条目时使用空列表，不虚构配置 ID。
2. 定义类型与编解码器，新增字段为旧文件补默认值，但不得覆盖已有合法值。
3. 新建条目从该类别的 `newItem` 复制，并生成独立 id。
4. 用 `useWorkspacePresets` 注册文件名、编解码器和必填的 `defaults` 工厂；普通类别启用 `editableDefaults: true`，并在 `fixedFields` 声明系统代号或显示名称，不要另写一套自动保存逻辑。
5. 在预设设置增加上方系统默认值区和下方自定义编辑区，将 `flush` 接入 `prepareToLeave`；消费端使用同一 hook 的 `availablePresets`。系统固定名称使用文本，值使用编辑控件，不提供系统新增、删除操作；固定协议选项保持只读。
6. 验证系统值编辑、固定名称保护、系统完整性、候选顺序、旧数据兼容、自定义删除或清空后的重新加载、工作区隔离和保存失败重试。

## 公共事件预设

系统内置“玩家移动到指定位置”（`NOLOC_PlayerMoveToPoint`），入参依次为方式（Int32，默认 0）、X轴（Float，默认 0）、Z轴（Float，默认 0）。方式引用独立的「预设 → 移动方式」分类（`movementMethods.value`），与实体获取方式等预设分类同级。系统提供只读的行走（0）、跑步（1）、冲刺（2），下方可添加自定义整数预设，自动保存到当前工作区 `movementMethods.json`。运行时方式写入 `intParams[0]`，X、Z 按顺序写入 `floatParams[0..1]`。

系统内置“玩家传送”（`NOLOC_PlayerTeleport`），入参按设置位置、位置 X、位置 Y、位置 Z、设置旋转、旋转 Y 排列。两个开关均为 Bool，默认 `False`，分别写入 `boolParams[0]`、`boolParams[1]`；设置位置为 `True` 时显示位置 XYZ，设置旋转为 `True` 时显示旋转 Y。四个数值均为 Float，默认值为 0，仍按位置 X、位置 Y、位置 Z、旋转 Y 的顺序写入 `floatParams[0..3]`，关闭开关时以 0 占位并保留工程中的原值。

参数可用 `visibleWhen: [{ parameterId, equals }]` 配置显示条件，多个条件按“且”组合；所有公共事件的参数编辑区均提供条件配置。条件按稳定参数 ID 引用，更名或重排不影响引用，删除来源后保持字段显示以便修正。显示条件跟随当前预设：预设成功保存或对话重新打开后，按已保存的预设 ID、参数 ID 和类型同步现有 Clip 的条件，包括未打开参数面板的片段；新增、修改和删除条件均生效。事件名、参数值、来源和结构仍保留原快照；预设缺失或被引用的参数 ID／类型不匹配时保留原条件，旧 Int32 控制参数不套用新 Bool 条件。隐藏不会清除已填写值；导出前同步整个当前对话的条件，隐藏参数使用字符串空值、数值 0 或布尔值 `False` 占位，保留各类型参数列表的顺序。

公共事件的手填参数、默认值、条件匹配值及自定义配置记录使用 `TypedValueInput.vue`，按数据类型限制键入和粘贴：Int32 支持正负整数；Float 支持小数和科学计数；GUID、配置 ID、元件 ID 仅接受非负整数文本；String 自由输入文字；Bool 仅提供“否 / 是”下拉，分别保存 `False` / `True`，默认否，不提供“未设置”。切换为 Bool 时默认值初始化为 `False`，读取缺失或为空的布尔默认值时也补 `False`，已保存的合法 `True` 保留。条件匹配值使用来源参数的类型，来源缺失时保留文字编辑能力。数值输入允许负号、小数点和指数等中间草稿，失焦后标记未完成或超范围的值；数值空值仍可作为可选草稿，导出继续校验必填数值。非法整段输入直接拒绝，不将小数或文字拆成其他数字；GUID 不经过 Number 转换，数值切换类型和加载旧数据不会自动改写值。

Bool 参数写入 ActionClip 末尾的 `boolParams`（BoolList），各项必须为 `True` 或 `False`，同类型顺序保持不变，上限 100 项。可直接选择“否 / 是”，也可引用自定义 Bool 字段。旧的“布尔值”预设类别、系统配置和 `booleans.value` 值来源已删除，旧 `booleans.json` 不再读取。已保存的 Int32 参数保持整数类型及原 0／1 值，legacy `booleans.value` 引用保留在快照中，但编辑时回退为 Int32 手填输入，不自动迁移为 Bool。运行时导入恢复 Bool 参数为同样的字符串值；旧版 ActionClip 仅缺少末尾 `boolParams` 时按空列表读取，其他缺失字段仍报错。

默认“触发实体朝向（仅物件）”的“设置朝向（否＝重置）”为 Bool，默认 `False`。始终显示实体1配置，值为否时重置实体1并隐藏实体2，为是时显示两组实体配置；每组按 GUID（0）或 String（1）只显示对应的输入。旧 Int32 片段仍按 0／1 控制条件。

默认“重置镜头”（`NOLOC_ResetCamera`）的参数“是否立即到达”为 Bool，默认否（`False`），直接选择“否 / 是”并导出至 `boolParams`。实体获取方式仍仅提供只读的 GUID（0）、String（1），该固定类别不能新增、编辑或删除选项；旧工作区自定义文件保留，不加入候选列表，不改写已有 Clip，对应参数导出至 `intParams`。

系统内置“播放简单黑幕”（`NOLOC_SimpleBlackScreen`）：颜色为 String，默认 `#000000FF`，写入 `stringParams[1]`（索引 0 为事件名），由游戏端解析 `#RRGGBB` 或 `#RRGGBBAA`；过渡时间、持续时间、淡出时间为 Float，默认依次为 `0.5`、`1`、`0.5`。浮点参数按同类型顺序写入新版 ActionClip 的 `floatParams`（FloatList），并校验有效数值及浮点范围。

系统内置“玩家播放技能动画”，事件名 `NOLOC_PlayerSkill`。参数“技能配置 ID”为 `ConfigReference`，引用 `skillAnimations.configId`，默认值为空，使用时选择技能动画。

公共事件按“代号（alias）、事件名（name）、参数（parameters）”配置。代号仅用于网页显示与搜索，不写入事件名或导出参数；未填写代号时显示事件名。旧自定义文件缺少 alias 时以原事件名补齐，显式空代号保留。系统项的代号固定，事件名及全部参数均可自定义修改；自定义项的代号也可编辑。

每个公共事件的参数设置区默认折叠，展开控件与代号、事件名位于卡片顶部同一行的右侧；点击“参数设置”可展开或再次折叠。折叠后保留代号和事件名、参数数量及事件操作，隐藏参数字段和显示条件配置。展开状态属于当前界面的展示状态，不写入预设、不进入撤销历史，也不影响参数保存和导出。

在「预设公共事件」中配置事件名，以及每个参数的名称、类型和默认值。事件名写入 `NOLOC_TRIGGERPUBLIC` 的 `stringParams[0]`，字符串参数从索引 1 开始；整数、GUID、配置 ID、元件 ID、Float、Bool 分别写入 `intParams`、`guidParams`、`configParams`、`prefabParams`、`floatParams`、`boolParams`，各自从索引 0 开始并保持同类型参数的定义顺序。

Public Event Clip 通过预设下拉选择事件，不提供独立事件名输入框。套用预设时复制事件名和参数定义并按名称显示参数输入框，GUID 保留为文本以避免精度丢失。预设及参数引用的弹出菜单标记为 Clip 编辑器区域，点击选项不会触发外部关闭。修改预设仅自动同步已有 Clip 的显示条件；重新选择同一预设时刷新其余定义，并按参数 ID 和类型保留已填写的值。旧版单字符串预设迁移为一个字符串参数，旧 Clip 的事件名保持原值；预设缺失时只读提示已保存的事件名。

预设由 `useWorkspacePresets` 将系统值覆盖和自定义项分别保存在工作区的 `PublicEventPresets.json`；系统条目与新建默认值统一定义在 `systemPresetConfig.publicEvents`。系统代号固定，其余值可编辑；系统项不能新增或删除。

## 多字段自定义配置与公共事件引用

系统配置类别内，上方展示只读系统字段，下方可以新增、编辑、删除自定义字段。系统记录的名称及系统字段值只读，其自定义字段值可以填写；用户新增的记录可以编辑全部字段。系统类别和字段仍在 `systemPresetConfig.customTables.presets` 中定义，目前系统类别列表为空。

用户扩展以独立条目保存在 `CustomPresets.json`，通过可选的 `extends` 指向系统类别 ID，只保存新增字段及用户填写的记录值。消费端的 `availablePresets` 按系统类别 ID 合并，公共事件可引用合并后的全部字段；系统字段和系统记录原值优先，不能被扩展覆盖。系统类别移除后仍保留扩展及原引用 ID，显示为可编辑的自定义类别；已有无 `extends` 的自定义类别保持兼容。

「自定义配置」可创建多个类别。每个类别包含字段定义（稳定 ID、名称、数据类型）和记录（稳定 ID、显示名称、按字段 ID 保存的值）。支持 String、Int32、Float、Bool、配置 ID、元件 ID、GUID；数值和布尔值均以字符串保存，GUID 不转换为 JavaScript Number。字段更名不会丢失记录值，新增字段不会覆盖旧数据。文件为工作区 CustomPresets.json，默认字段集中在 systemPresetConfig.customTables。

公共事件参数的“值来源”可以选择兼容类型的预设字段，包括技能配置 ID、实体人名/副标题、样式值、事件名和自定义字段。reference 保存来源键，自定义键由类别与字段 ID 编码组成。Timeline 提供记录下拉，选择时只复制字段值；已保存的 Clip 保留来源信息和值，导出仍按原来的类型列表写入。配置了值来源的参数仅显示记录下拉，不同时提供手动输入框；未配置来源时才显示输入框。来源被删除或更改类型时保留原值，并提示在预设设置中修正来源，不依赖来源存在才能导出。单个来源读取失败不会禁用其他来源的下拉。

配置页采用分类导航，预设编辑区顶部的同一个“词条”按钮控制左侧词条／代号浏览面板，展开和收起时按钮位置保持一致。展开列表采用透明底，融入原淡紫布局；仅列出当前选中分类的词条，按系统／自定义分组，使用紧凑的代号／显示名称。完整事件名等实际值用于搜索匹配，搜索同时匹配名称、代号及实际值。点击词条定位当前分类中的对应卡片，切换分类时清空搜索。收起时整块词条栏及其边界隐藏，编辑区恢复全宽，不留下竖线或悬浮把手；顶部按钮保留，收起期间保留搜索值和浏览界面状态，再次展开时继续使用。浏览面板、搜索和定位只影响界面，不写入预设、不进入编辑历史；列表复用已挂载编辑器的预设状态，编辑后及时更新。

各分类保持挂载以保留自动保存队列，所有保存队列均纳入离开前刷新。公共事件使用完整宽度的参数卡片，参数名称、类型、值来源和默认值按卡片可用宽度自适应为四列、两列或一列。显示条件位于独立的全宽区域，每条规则分行排列，增删条件及参数操作按钮在当前宽度内可见；公共参数区不使用横向滚动。自定义记录表格仍可横向滚动，字段数量不需要硬编码 UI。

所有可编辑预设分类均支持工具栏撤销／重做及 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+Y，当前分类保留最近 100 步，切换分类后仍可恢复。系统预设的值修改与自定义条目的增删改共同进入完整历史快照，系统固定名称保持种子值，系统行不能删除；类别、字段、记录及公共事件参数的增删改都纳入历史，删除字段可连同其全部记录值一起恢复。固定协议选项只读，参数区折叠状态不进入历史。恢复结果仍自动保存。接入与文档边界见 [编辑历史](../EDITOR_HISTORY.md)。

## 存档模块

入口为「预设 → 其他 → 存档模块」。100 项整数（下标 0–99）各自转换为完整的 32 位二进制，最低位 bit 0 在左、符号位 bit 31 在右，再按下标顺序拼成 3200 位：整数 [0] 的 32 位后面接 [1]、[2]，直到 [99]。全局位编号为 `整数下标 × 32 + bit 位号`；例如全局位 0 是整数 [0] 的最低位，全局位 31 是其符号位，全局位 32 是整数 [1] 的最低位。数值 `1` 显示为左侧一个 `1` 后接 31 个 `0`，选择起始位 0、长度 1 即读取 `1`。负数按 Int32 补码显示，因此 `-1` 显示为 32 个 `1`。

在拼接后的二进制上点击两个端点，或拖动选择连续的一段，再填写全局起始位、长度及这一段表示的内容字符串并保存。位段可以跨越多个整数，不受 32 位限制；例如起始位 28、长度 12 包含整数 [0] 的 bit 28–31 和整数 [1] 的 bit 0–7。选中段也按低位在左显示，起始位对应该字段的最低有效位，向右位权依次为 `1、2、4、8…`，跨整数时连续递增。切换整数用于查看相邻位置和编辑该项十进制预览，保留当前位段草稿。所有已保存位段始终列出，可选择、编辑和删除，覆盖的整数行同时显示位段标记。界面展示完整的选中段二进制及精确的十进制值：恰好 32 位时按有符号 Int32 解读，范围为 `-2147483648–2147483647`，包括跨整数的 32 位段；1–31 位及超过 32 位仍按无符号值解读，长位段超过 JavaScript 安全整数范围时也保持精确。展开「数值范围」可设置最小值／最大值，默认采用位段完整范围，切换位段长度时默认范围随之更新，合法的自定义子范围保留；无效位区间、超出容量的范围和全局位段重叠会阻止保存。无需先创建模块，也不显示系统默认／自定义模块分组。

位段定义通过 `useSaveModules` / `useWorkspacePresets` 自动保存到当前工作区的 `SaveModules.json`。新版使用 `schemaVersion: 2`，字段为 `id`、`name`、全局 `startBit`、`length` 及十进制字符串 `min`／`max`。旧版单整数定义按 `全局起始位 = integerIndex × 32 + startBit`、`长度 = endBit - startBit + 1` 迁移，保留原位段实际含义、模块与字段 ID 和名称。已有 v2 定义的起始位和长度保持原数值，统一按低位在左的位序读取。合法 32 位段的已知旧完整范围 `0–4294967295`（v1 或 v2）转换为有符号完整范围；自定义范围及无效草稿不自动改写。仅加载文件不会自动写回；无效旧位段仍保留并显示，用户可以修正或删除，并通过历史恢复。增删改支持预设历史，保存队列纳入编辑器离开前刷新；结构损坏文件不自动覆盖。

「导入存档 GIA」准确读取原生存档资产结构中的「游戏实体状态列表」，要求类型为整数列表且长度恰好为 100。存在多个结构实例时显示实例下拉供选择。解析 packed protobuf 原始字节，避免转换器推断全零列表为对象后丢失顺序；支持零值、uint32 及符号扩展 int32 负数。导入失败保留已有预览。使用 `saveModuleGia.ts`，转换器按需加载。

导入后，列表及二进制字符串立即显示该实例的 100 项整数。可以手动修改选中整数的十进制预览值，并恢复当前实例的导入值。预览数据属于当前编辑会话，不写入 `SaveModules.json` 或源 GIA，选择整数或修改预览值时即时更新位段解码结果。

回归命令：`node scripts/test-dsfg-save-modules.cjs`、`node scripts/test-dsfg-save-module-gia.cjs [存档.gia]`、`node scripts/test-dsfg-save-module-editor.cjs`。
