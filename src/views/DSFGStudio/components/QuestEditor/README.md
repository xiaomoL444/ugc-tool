# 任务编辑器

工作区内通过「编辑内容：对话 / 任务」切换。对话仍使用原来的多文件编辑器；每个工作区只维护一份任务配置，任务模式不再提供任务文件列表、新建文件或删除文件入口。进入任务模式会自动读取或首次创建 `/<工作区>/QuestEditor.json`，其中仍可编排多个章节、主任务和子任务。实际路径由现有 StorageClass 加上 DSFGStudio 项目前缀，使用浏览器存储，不写回外部结构体导出目录。

## 旧任务文件沿用

- 已存在工作区固定配置时，优先且只读取该配置；读取或校验失败会显示错误及重试入口，不会用空配置覆盖原数据。
- 尚无固定配置时，检查原 `/<工作区>/QuestEditor/` 目录。没有旧文件则自动创建；只有一份则直接沿用；多份时要求一次性选择一份，未选择前不创建、不合并任何任务数据。
- 沿用的内容保存到固定路径，原文件全部保留为备份，不删除、不改变 ID、引用或结构体设置。创建或沿用必须保存成功后才开放编辑。
- 存储路径在面板挂载时固定。切换工作区前保存完成；过期读取不能覆盖新面板，也不能向另一个工作区写入。

## 数据与层级

`QuestProject` 保存章节、主任务、子任务三个独立列表，通过稳定的整数 ID 关联。可先创建章节，也可直接创建不归属章节的主任务。章节和主任务各最多 100 个；子任务整个文件最多 10,000 个（ID 0–9999）。移动归属或改名不重新编号。删除章节仅解除下属主任务的章节归属；删除主任务时会提示并删除它的子任务。

树支持折叠、搜索与分页，子任务每页 50 项。右侧编辑结构体对应属性；调查点复用 PositionSlot 的空间、点位类型、坐标、GUID、Entity、挂接点、偏移和客户端位置参数。

章节按 `id`、`标题` 导出；主任务按 `id`、`chapter`、`title`、`style` 导出。首位 `id` 为条目自身已有的稳定 ID，与对应字典键相同，不是结构体类型的 `structId`，也不是父级 ID。编辑器已经保存这些 ID，旧文件无须新增另一套编号。编辑器仍用 `chapterId` 保存章节归属，导出时映射到 `chapter`；无章节标记规则不变。「主任务样式」是自由文本，默认 `Mainline`。新建主任务与打开缺失 `style` 的旧文件都会采用该默认值；已填写的自定义样式或空字符串不会被覆盖，保存和导出均保留原文。

子任务的「后续任务」对应结构体追加的 `Int32List` 字段，编辑器字段为 `nextQuestIds`。默认空列表，可添加、修改、排序及移除，最多 100 项。填写的是完整 ID（例如 100），不转换成字典桶号或余数；保留重复项和用户顺序。删除子任务（包括删除主任务时连带删除其子任务）会将其余任务指向已删除子任务的全部引用置为 `null`，保留列表位置、数量及其他任务的 ID，不重新编号。删除时仅处理实际被删除的 ID，不清空指向尚未创建或外部任务的其他引用。即使新建任务复用了已删除的 ID，原引用也会保持为空，不会自动指向新任务。

打开旧工程时，仅为缺失该字段的子任务补空列表。保存、Ctrl+S 和重新打开工程均保留 `null` 空位；千星结构体的 `Int32List` 不支持空值，因此导出时将空位转为 `-1`，并按来源子任务 ID、标题和列表位置汇总警告。对当前文件中不存在的数值 ID，导出同样提示警告但保留原值，以支持尚未创建或外部任务的引用。默认的空列表 `[]` 表示没有后续任务，不产生缺失引用警告。

## 新版子任务结构体

子任务采用 `1077936145[任务]子任务.json` 的新版定义，按以下 12 个字段顺序通过结构体库导出。内部编辑器字段名保持稳定，旧数据的标题、描述、归属关系及 ID 不会因为结构体字段更名而丢失。

| 导出字段 | 编辑器字段 | 类型 / 新建默认值 |
| --- | --- | --- |
| id | id | Int32 / 子任务自身完整 ID |
| mainQuestId | mainQuestId | Int32 / 归属主任务 ID |
| title | title | String / 新子任务 |
| desc | description | String / 空文本 |
| 任务单位状态 | unitState | ConfigReference / 0 |
| 任务调查点预设点 | investigationPoint | Struct / PositionSlot |
| 调查点范围 | investigationRange | Float / -1 |
| 隐藏任务 | hidden | Bool / false |
| 后续任务 | nextQuestIds | Int32List / 空列表 |
| 失败回溯任务 | failureQuestId | Int32 / -1 |
| finishMainQuest | finishMainQuest | Bool / false |
| questProgress | questProgress | Int32 / 0 |

失败回溯填写完整子任务 ID，不转换成字典桶号。默认 `-1` 不产生引用警告；主动清空或删除目标任务后，编辑器保存 `null`，导出为 `-1` 并警告。当前工作区不存在的其他 ID 会警告但保留原值。删除主任务时也清空指向其下已删除子任务的回溯引用；其他任务 ID 保持不变，重新创建相同 ID 不会恢复旧引用。

打开旧配置时只补齐缺失的三个新增字段，已有 `0`、`false`、`null` 等值不会被默认值覆盖。完成主任务是独立复选框；任务进度按 Int32 原值导出，不推断百分比、完成阈值或与复选框的联动。

## 保存和导出

- 修改自动保存当前工作区的唯一任务配置；切换工作区或编辑器前等待保存成功。Ctrl+S 下载可编辑的 `<工作区>-任务.json`。
- 「导出千星任务」直接下载 `<工作区>-任务配置数据.json`，用于替换单个任务配置变量，不再生成 ZIP 或三份分离变量。编辑器 JSON 下载仍用于继续编辑，格式与运行时结构体不同。
- 使用 `miliastra-variable` 的 `VariableWorkspace` / `VariableValue` 注册结构体、填充命名字段和序列化，未手拼结构体字段序号。
- 外层为 `1077936169`「任务配置数据」结构体，按源定义依次包含 `章节`（Int32 → Struct 字典）、`主任务`（Int32 → Struct 字典）、`子任务`（Int32 → StructList 字典）。配置定义/示例中的演示条目会清空，再填入当前工程；空工程导出三个空字典。
- 子任务桶键仍为 `Math.floor(id / 100)`，但桶值现在直接是子任务结构体列表，不再使用 `1077936167`「子任务字典」包装，也没有内层字典键。每桶按完整 ID 升序排列，最多 100 项；空桶不导出。
- 每个子任务结构体首位 `id` 保留完整自身 ID。例如 ID 100 和 199 都进入桶 1，列表中分别保存 `id=100`、`id=199`。删除产生的缺口不填充空白/虚构任务，不能把列表位置当作任务 ID。父级关系、后续任务、回溯引用与原有删除置空规则保持不变。
- 结构体 ID 设置覆盖任务配置数据、章节、主任务、子任务、PositionSlot，并递归更新外层、字典类型、结构体列表及嵌套结构体 ID。打开旧工程时仅补缺失的 `configuration=1077936169`，移除停用的 `subQuestDictionary` 设置；不复用其旧 ID，不改其他自定义 ID 和任务数据。新配置已有自定义外层 ID 时按原值保留。
- 无章节主任务默认用 -1 表示归属章节，可在结构体 ID 设置窗口修改；须与运行时约定一致，不可撞到已有章节 ID。

## 结构体来源

`src/assets/DSFGStudio/Quest` 是用户目录「结构体导出 / V2.0」的源文件副本。统一导出参考 `1077936169[任务]任务配置数据.json` 和 `任务配置数据变量.json`。旧子任务字典定义及三个 NOLOC 样例仅作为历史参照保留，不再注册或参与导出。子任务内嵌调查点样例比独立 PositionSlot 多两个未命名 Int32，当前仍使用独立 PositionSlot 的 8 个命名字段，导出会提示此已有差异；若运行时需要这两个字段，需要补齐它们的命名定义。不猜测额外字段含义，不影响对话编辑器原结构体资源。

核心：`questProject.ts`（模型/草稿编解码/校验）、`questExporter.ts`（结构体库导出）、`QuestPanel.vue`（纯层级编辑）、`QuestEditor.vue`（文件/保存/下载）、`workspaceSaveQueue.ts`（固定路径快照的串行保存队列）。

回归：`node scripts/test-dsfg-quest-export.cjs`、`node scripts/test-dsfg-workspace-save.cjs`、`node scripts/test-dsfg-quest-integration.cjs`。
